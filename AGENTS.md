# AGENTS.md

## О проекте

- Это учебный task-трекер для управления списком задач.
- Интерфейс и пользовательские тексты приложения — на русском языке.
- Актуальный план развития хранится в `.codex/.plans/projects.md`.
- Не считать `README.md` или план заменой этому файлу: здесь находятся постоянные правила работы с репозиторием.

## Стек и команды

- React 19, TypeScript 6, Vite 8 и обычный CSS.
- Пакетный менеджер: npm. Не создавать lock-файлы других пакетных менеджеров.
- Запуск разработки: `npm run dev`.
- Проверка линтером: `npm run lint`.
- Production-сборка: `npm run build`.
- Локальный просмотр сборки: `npm run preview`.

## Текущая структура

- `src/App.tsx` собирает интерфейс и координирует состояние фильтрации и редактирования.
- Компоненты находятся в `src/components`; стили каждого компонента хранятся рядом с ним.
- Операции со списком задач находятся в `src/hooks/useTasks.ts`.
- Типы, константы и работа с `localStorage` разделены между `src/types`, `src/constants` и `src/utils`.
- `src/App.css` содержит только стили каркаса приложения, а `src/index.css` — глобальные стили.
- Статические ресурсы находятся в `src/assets` и `public`.
- Не редактировать вручную `dist` и `node_modules`.

## Продуктовые правила

- Текст новой задачи после `trim()` должен содержать от 1 до 80 символов.
- Кнопка добавления должна быть недоступна для пустого значения и строки из пробелов.
- Добавление, удаление и изменение статусов должны обновлять список без перезагрузки страницы.
- У задачи есть независимые статусы `isImportant` и `isCompleted`.
- Важная задача выделяется жирным шрифтом и красным акцентом.
- Выполненная задача выделяется зелёным цветом и курсивом без зачёркивания текста.
- Переключение визуальных состояний должно быть плавным и не вызывать задержки изменения шрифта или бликов.
- Задачи и оба статуса сохраняются в `localStorage` по ключу `focus.task-tracker.tasks`.
- При изменении формата сохранённых данных по возможности поддерживать ранее созданные задачи.

## Правила разработки

- Использовать функциональные React-компоненты и хуки.
- Не возвращать бизнес-логику и разметку компонентов обратно в монолитный `App.tsx`.
- Компоненты не должны напрямую обращаться к `localStorage`; использовать `useTasks` и `taskStorage`.
- Состояние обновлять иммутабельно; задачу идентифицировать по `id`.
- Сохранять строгую типизацию и не использовать `any` без обоснованной необходимости.
- Не добавлять зависимости и не менять основной стек без согласования с пользователем.
- Сохранять существующий визуальный язык, адаптивность и плавность интерфейса.
- Поддерживать доступность: семантическая разметка, связанные `label`, понятные `aria-label` и управление с клавиатуры.
- Ошибки чтения или записи `localStorage` не должны делать приложение неработоспособным.
- Не очищать пользовательские данные в `localStorage`, если этого прямо не требует задача.
- Не выполнять крупный рефакторинг, не связанный с текущей задачей.

## Проверка изменений

- После изменения кода выполнять `npm run lint` и `npm run build`.
- Для изменений интерфейса вручную проверять приложение в браузере.
- При изменениях списка проверять добавление, удаление, оба статуса и сохранение данных после обновления страницы.
- Проверять граничные случаи формы: пустая строка, только пробелы, 1 символ и 80 символов.

## Git

- Перед завершением работы просматривать diff и не включать посторонние изменения.
- Не создавать commit и не выполнять push без прямой просьбы пользователя.
- Для названий коммитов использовать Conventional Commits, например `feat:`, `fix:`, `refactor:` или `docs:`.
