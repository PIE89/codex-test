# План разработки task-трекера

Будем делать базовый task-трекер на React + TypeScript. На первом этапе задачи хранятся в памяти приложения: после обновления страницы список обнуляется. Сохранение в `localStorage` можно добавить позже отдельным этапом.

## Что должно получиться

Приложение состоит из двух основных частей.

### Форма добавления задачи

- управляемое текстовое поле;
- максимальная длина введённого значения — 80 символов;
- справа от поля находится кнопка «Добавить»;
- кнопка имеет состояние `disabled`, пока поле пустое или содержит только пробельные символы;
- задача добавляется отправкой формы — кнопкой «Добавить» или клавишей Enter;
- перед сохранением пробелы в начале и конце удаляются;
- после успешного добавления поле очищается, а кнопка снова становится недоступной.

### Динамический нумерованный список

- новая задача добавляется в конец списка;
- возле каждой задачи находятся кнопки «Важно» и «Удалить»;
- кнопка «Удалить» удаляет конкретную задачу;
- кнопка «Важно» переключает состояние и оформление конкретной задачи;
- после удаления нумерация автоматически перестраивается.

## Подробный план

### 1. Подготовить модель задачи

Описать TypeScript-тип `Task` со следующими полями:

- `id` — уникальный идентификатор;
- `text` — текст задачи длиной не более 80 символов;
- `isImportant` — признак важной задачи.

```ts
type Task = {
  id: string
  text: string
  isImportant: boolean
}
```

Уникальный идентификатор позволит изменять и удалять конкретную задачу, даже если несколько задач имеют одинаковый текст.

### 2. Определить состояние приложения

В главном компоненте предусмотреть два состояния:

- текущее значение текстового поля;
- массив добавленных задач.

```ts
const [taskText, setTaskText] = useState('')
const [tasks, setTasks] = useState<Task[]>([])
```

При изменении поля обновляется `taskText`. При добавлении, удалении или изменении важности обновляется `tasks`.

### 3. Создать форму добавления

Разместить в элементе `<form>`:

- `<input>` для текста задачи;
- `<button type="submit">Добавить</button>` справа от поля.

Поле сделать управляемым:

- `value` получает значение из `taskText`;
- `onChange` обновляет `taskText`;
- `maxLength={80}` не позволяет ввести более 80 символов.

Кнопку расположить справа с помощью Flexbox или Grid. Форму обрабатывать через `onSubmit`, чтобы она работала одинаково при нажатии кнопки и клавиши Enter.

### 4. Реализовать проверку введённого текста

Для проверки использовать очищенное значение:

```ts
const normalizedTaskText = taskText.trim()
const isTaskValid =
  normalizedTaskText.length > 0 && normalizedTaskText.length <= 80
```

Кнопка «Добавить» должна получать:

```tsx
disabled={!isTaskValid}
```

Добавить нельзя:

- пустую строку;
- один или несколько пробелов;
- строку только из пробельных символов и переносов;
- текст длиннее 80 символов.

Ограничение должно присутствовать и в интерфейсе через `maxLength`, и в обработчике отправки. Повторная проверка в обработчике защищает логику приложения независимо от состояния HTML-поля.

Строку вида `"  Купить молоко  "` можно добавить, но перед сохранением внешние пробелы нужно удалить. Под символом понимается любой непробельный символ: буква, цифра или знак.

### 5. Реализовать добавление задачи

При отправке формы:

1. Вызвать `event.preventDefault()`.
2. Получить значение через `trim()`.
3. Повторно проверить, что длина результата находится в диапазоне от 1 до 80 символов.
4. Создать задачу с уникальным `id` и `isImportant: false`.
5. Добавить задачу в конец массива.
6. Очистить текстовое поле через `setTaskText('')`.

После очистки кнопка «Добавить» автоматически снова станет недоступной.

### 6. Создать нумерованный список

Для семантически правильной нумерации использовать `<ol>` и `<li>`. Массив задач преобразовывать в элементы списка через `tasks.map()`.

В качестве React-ключа использовать `task.id`, а не индекс массива. Тогда удаление элемента не нарушит соответствие задач и элементов интерфейса.

### 7. Описать вид одной задачи

Каждый пункт списка должен содержать:

- номер, создаваемый элементом `<ol>`;
- текст задачи;
- кнопку «Важно»;
- кнопку «Удалить».

При необходимости пункт можно вынести в компонент `TaskItem`:

```ts
type TaskItemProps = {
  task: Task
  onToggleImportant: (id: string) => void
  onDelete: (id: string) => void
}
```

Для первой учебной версии допустимо оставить всю логику в `App.tsx`, а разделить её на компоненты после появления рабочей версии.

### 8. Реализовать удаление

Кнопка «Удалить» передаёт `id` выбранной задачи. Из массива исключается элемент с этим идентификатором:

```ts
tasks.filter((task) => task.id !== id)
```

React перерисует список, а `<ol>` автоматически пересчитает номера оставшихся задач.

### 9. Реализовать кнопку «Важно»

По нажатию найти задачу по `id` и переключить значение:

```ts
isImportant: !task.isImportant
```

Первое нажатие отмечает задачу как важную, повторное снимает отметку. Важную задачу выделить фоном, рамкой, начертанием текста или цветом кнопки.

Кнопке добавить атрибут:

```tsx
aria-pressed={task.isImportant}
```

Перемещать важные задачи наверх на этом этапе не требуется.

### 10. Добавить состояние пустого списка

Пока задач нет, вместо пустого списка вывести сообщение «Задач пока нет». После добавления первой задачи сообщение исчезает и появляется список.

### 11. Оформить интерфейс

Предусмотреть стили для:

- общего контейнера и заголовка;
- формы, текстового поля и кнопки справа;
- активной кнопки «Добавить» и её состояния `disabled`;
- нумерованного списка и отдельного пункта;
- обычной и важной задачи;
- кнопок «Важно» и «Удалить»;
- состояний наведения и фокуса;
- небольшого экрана.

Заблокированная кнопка должна визуально отличаться от доступной, но текст оставаться читаемым.

### 12. Проверить пограничные случаи

Проверить:

- пустое поле;
- один и несколько пробелов;
- пробельные символы и переносы без текста;
- ввод 1 символа;
- ввод ровно 80 символов;
- невозможность ввести 81-й символ;
- повторную защитную проверку длины при отправке формы;
- текст с пробелами по краям;
- добавление кнопкой и клавишей Enter;
- очистку поля после успешного добавления;
- последовательное добавление нескольких задач;
- одинаковый текст у нескольких задач;
- удаление первой, средней, последней и единственной задачи;
- переключение важности несколько раз;
- правильную нумерацию после удаления.

### 13. Провести техническую проверку

После реализации выполнить:

```powershell
npm run lint
npm run build
```

Затем запустить приложение:

```powershell
npm run dev
```

Проверить поведение вручную в браузере и убедиться, что в консоли нет ошибок.

### 14. Сохранить результат в Git

Перед фиксацией результата проверить состав изменений:

```powershell
git status
git diff
```

После проверки создать коммит. Отправку в удалённый репозиторий выполнять отдельно, когда это потребуется.

## Этапы реализации

### Текущий этап: только форма

На текущем этапе реализовать:

- управляемое поле с ограничением 80 символов;
- кнопку «Добавить» справа;
- `disabled` для пустого значения и одних пробелов;
- отправку формы кнопкой и клавишей Enter;
- очистку поля после успешной отправки.

Список, важность и удаление пока не реализовывать.

### Следующий этап: список и действия

После завершения и проверки формы добавить модель задачи, массив задач, нумерованный список, отметку важности и удаление.

## Критерии готовности всего проекта

Проект можно считать готовым, если:

- пользователь может ввести от 1 до 80 символов;
- в поле невозможно ввести более 80 символов;
- пустую строку или строку из пробелов добавить нельзя;
- кнопка «Добавить» правильно включается и отключается;
- задача добавляется кнопкой и клавишей Enter;
- поле очищается после успешного добавления;
- задачи отображаются в динамическом нумерованном списке;
- каждую задачу можно отметить как важную и снять отметку;
- каждую задачу можно удалить;
- после удаления нумерация остаётся правильной;
- в консоли браузера нет ошибок;
- `lint` и `build` проходят успешно.
